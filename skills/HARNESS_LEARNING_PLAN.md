# Harness 学习方案

> 适用对象：日常使用 Arch Linux、偏好终端工作、正在搭建短剧创作工作流，并希望拥有自己的 Agent。

## 一、学习总目标

最终能够独立完成：

```text
一个故事创意
→ 人物与世界观
→ 分集大纲
→ 单集剧本
→ 连贯性检查
→ 格式检查
→ 输出交付文件
```

同时掌握：

- Harness、TUI 和 Web 的分工；
- 模型、后端、思考强度和 Agent 工具预设；
- 文件、Shell、MCP 等工具的使用；
- 权限、审批、Plan 和安全边界；
- Skill、Workflow 和自动检查；
- DSH、Codex 等不同后端的适用场景；
- 如何把 Harness 定制成自己的短剧 Agent。

---

## 二、先建立整体认识

Harness 可以理解为 Agent 的运行时和工作台：

- **模型**负责理解、推理和生成内容；
- **工具**负责读写文件、执行命令和调用外部服务；
- **Harness**负责组织任务、管理上下文、控制权限和恢复会话；
- **TUI/Web**是不同的交互界面。

需要区分以下概念：

| 概念 | 作用 |
|---|---|
| 后端 Backend | DSH、Codex、Claude 等模型调用体系 |
| 模型 Model | 实际负责推理和生成内容的模型 |
| `effort` | 思考预算或推理强度 |
| `preset` | Agent 可以使用的工具组合 |
| `permission` | 文件、命令和系统访问权限 |
| `plan` | 先规划、后执行的协作模式 |
| Skill | 可复用的专业工作规范 |
| Workflow | 固定的多步骤任务流程 |

---

# 三、分阶段学习路线

## 阶段一：熟悉 TUI 基础

**建议用时：2～3 天**

### 学习目标

能够不依赖教程完成日常任务：

- 新建和恢复会话；
- 让 Agent 阅读项目文件；
- 修改文件并查看结果；
- 运行测试或检查命令；
- 中断并恢复任务；
- 调整模型、权限和计划模式。

### 优先掌握的命令

```text
/kernel       切换 DSH / Codex / Claude 后端
/model        切换模型
/effort       调整思考强度
/status       查看当前状态
/permission   调整权限
/plan         进入或退出计划模式
/preset       调整 Agent 工具预设
/compact      压缩会话上下文
/restart      重启并恢复会话
```

### 练习任务

1. 在当前项目中创建一个短剧主题文件；
2. 让 Agent 阅读项目结构；
3. 生成一份人物小传；
4. 让 Agent 修改文件；
5. 运行一次本地检查命令；
6. 查看 Git diff；
7. 中断任务后恢复会话。

这一阶段重点不是写出优秀剧本，而是理解：

> 模型如何读取文件、调用工具、执行命令、修改项目并继续任务。

---

## 阶段二：理解 Agent 的核心机制

**建议用时：3～5 天**

重点理解四个维度。

### 1. 模型

模型负责理解任务、推理和生成内容。

```text
/model
```

### 2. 工具

工具决定 Agent 能实际完成什么，例如：

- 读取和写入文件；
- 执行 Shell 命令；
- 搜索项目内容；
- 调用 MCP 服务；
- 使用 Skill；
- 委派子任务。

### 3. 权限

权限决定 Agent 是否可以执行操作：

- 只读；
- 工作区可写；
- 完全访问；
- 每次操作前审批。

日常开发建议默认使用工作区可写，需要时再批准额外操作。

### 4. Agent Preset

Preset 决定模型能看到哪些工具。

不要把以下概念混淆：

- `/effort`：思考预算；
- `/preset`：工具能力；
- `/permission`：安全权限；
- `/plan`：协作模式。

初期建议使用：

```text
/preset standard
```

等熟悉后，再尝试 `ptc`、`minimal` 等预设。

### 练习任务

让 Agent 按以下方式工作：

1. 先制定短剧生产计划；
2. 暂时不要修改文件；
3. 由你检查计划；
4. 获得批准后再执行。

通过这个练习理解 Plan、权限和工具调用之间的关系。

---

## 阶段三：学习 Skills

**建议用时：3～5 天**

Skill 是一套可复用的专业工作规范，适合把短剧创作规则固定下来。

### 短剧 Skill 可以规定

- 剧本格式；
- 场景标题格式；
- 人物首次出场规则；
- 对白长度；
- 单集字数；
- 冲突和节奏要求；
- 审稿标准；
- 输出文件位置；
- 禁止事项。

### 推荐的项目结构

```text
short-drama-workflow-v2/
├── skills/
│   ├── story-planning/
│   ├── character-design/
│   ├── episode-outline/
│   ├── script-writing/
│   └── script-review/
├── data/
│   ├── characters/
│   ├── world/
│   └── outlines/
├── episodes/
├── checks/
└── README.md
```

### 学习目标

- 知道 Skill 在什么情况下被调用；
- 能明确写出输入和输出；
- 能让多个 Skill 串联；
- 能防止 Agent 擅自改变设定；
- 能让不同会话保持统一风格。

---

## 阶段四：搭建第一个短剧 Agent

**建议用时：1 周**

不要一开始就做万能编剧 Agent，先完成一个稳定的最小版本。

### 第一版只实现五个阶段

```text
1. 故事创意分析
2. 人物设定
3. 分集大纲
4. 单集剧本
5. 连贯性审查
```

每个阶段都要明确：

```text
输入是什么
读取哪些文件
输出到哪里
使用什么格式
完成后如何检查
```

### 示例输出结构

```text
用户输入：
一个关于“失忆女主寻找真相”的短剧创意

Agent 输出：
- data/story-concept.md
- data/characters.md
- data/world.md
- data/episode-outline.md
- episodes/episode-01.md
```

### 建议加入的规则

- 不允许覆盖已有设定，除非用户确认；
- 生成新内容前必须读取人物表；
- 每集必须包含冲突、转折和结尾钩子；
- 修改后自动检查角色名和时间线；
- 发现矛盾时先报告，不擅自修改核心设定。

这一步的目标是让项目从普通聊天变成真正的 Agent 工作流。

---

## 阶段五：学习 Workflow 和自动检查

**建议用时：3～5 天**

当 Skill 稳定后，再学习 Workflow。

### 推荐的短剧生产流程

```text
创意输入
→ 人物生成
→ 世界观生成
→ 分集规划
→ 批量写作
→ 自动检查
→ 汇总报告
```

### 建议编写的本地检查脚本

- 检查集数；
- 检查字数；
- 检查角色名；
- 检查场景格式；
- 检查未闭合标记；
- 检查时间线；
- 检查文件命名；
- 检查重复或缺失场景。

Harness 负责：

- 理解内容；
- 调用工具；
- 决定下一步；
- 根据错误继续修正。

脚本负责：

- 做确定性的机械检查；
- 避免模型漏检；
- 让结果可重复。

核心原则：

> 创意交给模型，规则交给脚本。

---

## 阶段六：学习模型与后端切换

**建议用时：2～3 天**

在基础工作流稳定后，再深入 Codex 和其他后端。

### 需要区分

```text
后端：DSH / Codex / Claude
模型：具体使用的模型
effort：思考预算
preset：工具组合
permission：访问权限
```

### 对比练习

1. 用 DSH 完成一次短剧任务；
2. 用 Codex 后端完成同一个任务；
3. 比较以下方面：
   - 文件操作；
   - 命令执行；
   - Plan 行为；
   - 权限提示；
   - 上下文处理；
   - 输出风格；
   - 任务恢复能力。

不要一开始只追求哪个模型最强，先观察：

> 哪个后端最适合你的工作流。

---

## 阶段七：学习高级能力

基础能力稳定后，再学习：

- MCP；
- 子 Agent；
- 多 Agent 协作；
- CLI 无界面运行；
- 会话恢复；
- 插件；
- 自定义 preset；
- Web 与 TUI 配合；
- 日志和错误排查；
- Agent 安全边界。

### 可扩展的短剧 Agent 结构

```text
总编剧 Agent
├── 故事策划 Agent
├── 人物设定 Agent
├── 分集规划 Agent
├── 对白润色 Agent
└── 连贯性审查 Agent
```

建议等单 Agent 稳定后再拆分成多个 Agent，否则复杂度会快速增加。

# 四、推荐的每日学习方式

每天 60～90 分钟即可：

```text
20 分钟：阅读文档
30 分钟：完成一个小实验
30 分钟：改进短剧项目
10 分钟：记录经验
```

每次只研究一个主题，例如：

- 今天只研究 `/permission`；
- 明天只研究 Skill；
- 后天只研究 `/preset`；
- 再下一天研究会话恢复。

不要一次同时研究模型、MCP、插件和多 Agent。

---

# 五、阶段性验收标准

## 基础使用完成

你能够：

- 独立启动 TUI；
- 切换模型和后端；
- 调整权限和思考强度；
- 让 Agent 修改项目文件；
- 中断、恢复和压缩会话。

## Agent 配置完成

你能够：

- 写出清晰的 Skill；
- 配置工具和权限；
- 设计固定的短剧生产阶段；
- 让 Agent 按项目规则工作。

## 工作流完成

你能够：

- 一次输入创意并生成多阶段结果；
- 自动保存到固定目录；
- 自动运行格式和连贯性检查；
- 发现问题后让 Agent 继续修正。

## 高级能力完成

你能够：

- 判断 DSH、Codex 和其他后端的适用场景；
- 使用 MCP 或子 Agent；
- 运行无界面任务；
- 排查 Agent 执行失败的原因；
- 维护一个可复用的个人 Agent 系统。

---

# 六、最终建议

你的学习顺序应该是：

```text
TUI 操作
→ Agent 原理
→ Skill
→ 权限与模型
→ Workflow
→ 自动检查
→ 多 Agent 与 MCP
→ 插件和产品化
```

不要先研究底层源码，也不要一开始搭建复杂的多 Agent 系统。

先让一个简单的短剧 Agent 稳定完成：

```text
创意分析
→ 人物设定
→ 分集大纲
→ 单集剧本
→ 连贯性检查
```

然后再逐步扩展。

最终目标不是“会用 TUI”，而是拥有一个真正属于自己的：

> **短剧创作 Agent 工作台。**
