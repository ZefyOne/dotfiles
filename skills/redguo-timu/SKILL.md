# 红果短剧题材构思

**输入**：用户给的题材方向。AI 不自己选题材，方向由用户定。

**输出**：5 个提案。每个提案四栏——金手指、长期反派+关系、友方、切入点（第一集受辱）——加 3 个剧名。

不写剧情框架，不排集数，不设计分集。

## 第 0 步　确认方向与检索域

题材方向用户明说。先判断有没有可合并的邻域：

- 赶海 ↔ 赶山（金手指和人物关系互通，同一批样本能混用）
- 鉴宝 ↔ 鉴药、捡漏
- 两界穿越 ↔ 两界倒卖、两界直播

**动搜索之前先问一句**：「按 赶海+赶山 一起搜可以吗？」用户会给建议，按他的意见调整再搜。

**完成判据**：方向 + 检索词族写下来，用户点头。

## 第 1 步　检索同题材热剧

三条路，按顺序走：

```bash
python3 scripts/hongguo.py find 赶海 赶山 深海 海货 山货 渔村
```

`find` 匹配标题、标签和简介，命中里会混少量误报（简介顺带提一句也算），按简介过一遍再取。本地命中少是常态（榜单以玄幻都市为主），主路是站内搜索：

- `web_search` 用 `site:hongguoduanju.com 赶海`，再换词族多搜几轮（赶山、赶海记、千禧赶海、八零赶海、荒年赶山、赶海女王……）
- 结果里的 `detail?series_id=xxx` 或 `player/{id}/...` 都能取到 series_id
- 微博、百科、短剧百科等站的条目也带红果 id，能当索引

榜单兜底：`python3 scripts/hongguo.py digest` 看当期有没有同题材。

**完成判据**：手里 ≥6 个 series_id。

## 第 2 步　取详情，筛样本

```bash
python3 scripts/hongguo.py detail <seriesId> [<seriesId> ...]
```

输出含简介、集数、标签、收藏、点赞。筛选标准：

- **收藏 ≥10 万**，或**点赞明显高于收藏**（说明看完的人愿意互动）
- 不达标的别删，标成备用——样本不够时再启用

**完成判据**：≥5 部合格样本，每部都有简介和收藏/点赞数字。

## 第 3 步　按栏拆解

读 `references/extraction.md` 的拆解表。每部样本只填它能填的栏：

| 栏 | 合格判据 |
|---|---|
| 金手指 | 适配当前题材即可 |
| 长期反派 | 关系 **A/B 级**（配偶、父母兄弟、大伯二叔舅舅） |
| 友方 | **没金手指之前就对他好**的人：父母、妹妹、村里帮他的 |
| 切入点 | **先付出，再被背叛**；只有一层；落在**特殊时间**上（分家、除夕、满月酒、开海第一天） |

**不合格的栏直接空着，去下一部找。** 剧火不代表每栏都能用——24 万收藏的剧，照样可能只能贡献一个金手指。

关系分级、受辱类型、共鸣清单见 `references/shame.md`。

**完成判据**：拆解表填完，每栏标注来源剧，不合格的明确标“弃”。

## 第 4 步　交叉重组

5 个提案，每个提案的四栏来自**至少三部不同样本**：

```
金手指 ← 甲剧　长期反派 ← 乙剧　友方 ← 丙剧　切入点 ← 丁剧
```

- 切入点和长期反派最关键，优先挑 A 级
- 五个提案之间错开受辱类型：夺生存资料 / 被抛弃 / 当众羞辱，至少三种
- 三栏以上出自同一部剧就算抄，见 `extraction.md` 的反抄判定

**完成判据**：5 个提案，来源分散，受辱类型 ≥3 种。

## 第 5 步　查重

逐个提案跟拆解表里的每部样本比三栏，看有没有撞。

**撞车的定义是三栏同时命中**：金手指类似 **且** 人物关系类似 **且** 切入点一样。只中一栏、两栏都不算撞。判定表模板见 `references/extraction.md`。

- 三条都中 → 换切入点（换金手指或换关系也行，但换切入点最省）
- 只撞金手指或只撞关系 → 放过，不用改
- 撞了切入点但另外两栏不同 → 放过，这是正常取材

**完成判据**：查重表填完，每个提案都有「三栏交集」和「安全/撞车」的判定。

## 第 6 步　出剧名

每个提案 3 个，读 `references/titles.md` 的六个公式，走不同公式覆盖不同口味。

**完成判据**：15 个剧名，均 12 字左右，含手段词。

## 第 7 步　自检

逐条过，有一条不过就改：

1. 第一集只有**一层**受辱？（抢粮和出轨不能同时上）
2. 主角**先有倾其所有的付出**吗？付出和背叛拿的是不是同一件东西？
3. 主角占理吗？观众会不会觉得“换我也受不了”？
4. 受辱落在**特殊时间**上？（分家当天、除夕、满月酒，不能是“有一天”）
5. 长期反派是 A/B 级近亲？
6. 有没有提案三栏以上来自同一部剧？
7. 查重表里有没有三栏同时命中的？
8. 剧名是不是只换了一个词？

**完成判据**：八条全过。

## 输出格式

拆解表留内部备查，提案按下面这个格式出。**人物关系不单列**——反派是谁、友方是谁，都在切入点那一段里自然带出来。

```markdown
《剧名》/《剧名》/《剧名》

**切入点**：什么日子 + 主角倾其所有的付出 + 谁把这份付出拿走或否认 + 惨在哪 + 怎么觉醒金手指。一段话写完，要写出情绪。
**金手指**：是什么，能干什么。
**查重**：金手指像《…》、关系像《…》、切入点像《…》 → 三栏交集：无 / 撞车
```

切入点那一段是全部功夫所在。让读者一眼觉得“这人太冤了”，提案就成立。

末尾附两行：

- **数据口径**：样本来自哪几部剧、收藏点赞数
- **缓存目录**：把脚本最后打印的 `缓存目录：…` 原样带上。位置按系统走——Linux `~/.cache/redguo-timu`、macOS `~/Library/Caches/redguo-timu`、Windows `%LOCALAPPDATA%\redguo-timu`；沙箱不允许时会退到系统临时目录，照实写。
