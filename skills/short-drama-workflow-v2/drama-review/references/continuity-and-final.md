# 连续性、全剧终检与 Word 复核

## 五个阶段接哪一版

按集号读当前稿。续审先找到上一阶段实际末场，对照用户本次指定的正文、已确认的安排及题材要求。用户指定的前稿可以是附件、对话原文或几份连续分批稿。合稿逐字接入，发现错字、字数偏差或衔接疑点，在对话中指出集场。用户点名授权修改时，只动对应位置并复核牵动的后文。

| 当前审查范围 | 采用的前稿与重点接点 |
| --- | --- |
| 第1集 | 按确认的首集详案，核实开场处境、当场伤害、主角反应、能力首次显效和末句。记下末场谁看见了什么，供第2集承接。 |
| 第2–10集 | 读用户指定的第1集定稿，连读第1→2集。核对第2集行动是否用上末场得到的信息，人物口气是否接得上。按本批确认的逐集剧情和卡点审到第10集，收尾若留到第11集，记录待兑现的动作或反应。 |
| 第11–30集 | 读用户指定的前十集，连读第10→11集，再对照本批确认的逐集安排。采用默认打脸安排时，第10集末由首集反派亲眼见证优势，第11集在同一现场接反应、代价和离场。把这场回击与首集实际的羞辱对读。 |
| 第31–50集 | 读用户指定的第1–30集，连读第30→31集。按一次确认的第31–80集分段大纲和本批内部逐集安排审。通过的第31–50集修订稿留作内部稿，接入前三十集，记清第50集实际末场。 |
| 第51–80集 | 从上述内部前五十集接，连读第50→51集。按同一分段大纲和本批内部逐集安排查到结局。单独从第51集续写时，前稿改用用户指定的前五十集，后文对照本次确认的第51–80集安排。 |

每个交界都把上一集末句、动作、在场者、道具去向和已经发生的结果，与下集最先接上的一拍对读。冲突或交易横跨批次，就从起因读到实际兑现。下集尚无正文时，注明已核的计划和仍待核验的实际开场。定稿缺失或几份版本互相冲突时，标明具体集数和待明确的版本。

## 逐场追踪连续性

| 查什么 | 回到正文怎样核实 |
| --- | --- |
| 人物、关系与知情 | 查姓名、辈分、称呼、身份、态度和进出场。定位人物第一次叫出名字、认出身份或引用消息的台词，往前找本人在场看见、听见或获人转告的那一拍。人物栏、观众独享的 OS、后来才有的介绍都不能解释当时的知情。 |
| 能力、道具与证据 | 顺查首次显效、触发条件、对象、范围、代价、限制及解除时间。把旁人看见的成果与他亲见的运作过程分别核对。物件从取得、持有、交接、使用追到消耗或损坏。解围的物件和证据要能查到来源。 |
| 时空与动作 | 查当天、次日、期限和路程。连看上一场如何离开、下一场如何到场，货和人分别在哪儿。连续动作要看清站位、谁出手、作用于谁、谁在场看见及现场怎样改变。只指出影响理解的缺步。 |
| 伤势、资格与承诺 | 查受伤位置、当时活动能力、治疗和恢复的时间。已搬离、失去资格或被逐出的人再次出现，要能说明条件如何改变。核对承诺由谁对谁作出、何时到期、在哪一场兑现，删改前因后也回查仍在引用它的后文。 |
| 钱物、损益与归属 | 分清报价、成交、押金、欠款、赔偿和实收。把双方谈妥金额、当场交付、收钱及后文用款连起来读。金额已说清，交付动作能让观众看懂这笔账结清，就算兑现。正文出现短付、欠款、不同金额或后续支出对不上，再沿原句追差额。只有报价的那一刻，钱仍未到手。 |
| 合稿 | 逐集对独立参照，核对集号、场次、人物栏、漏集重集、同场两版、旧人名、旧道具、重复台词与编辑备注。修后连读改处前后场、受影响的卡点、下一集开头和后文再次提及该事的位置。 |

## 第1–80集终检

1. **先定全剧基准。** 按集号合入用户指定的第1–30集、实际用于续写的第31–50集内部通过稿，以及第51–80集通过稿。单独续写后三十集后合本，采用用户指定的前五十集。用户直接指定现成全本，就审该版本。从第1集按序读到第80集，同时检查各批交界及全剧每段实际的高潮、收尾和下一件事的起因。
2. **顺着各线查因果。** 按[本剧的双线或三线与阶段节奏](../../drama-planning/references/arc-and-pacing.md)对照确认的安排。赚钱线查主角靠什么本事、做了什么判断、收获怎样变现、钱解决了什么。无买卖的题材查当场可见的成果。反派线查谁如何知道这项成果、图什么利益、靠什么回场、本轮实际失去什么。三线剧再查哪次共同经历改变了谁的态度，后来哪次选择证明关系确实变了。
3. **试抽一轮，再试对调。** 对照相邻两轮的目标、阻碍、筹码、主角选择、结果和代价。抽掉前轮或互换顺序后，若资源、关系、行动和胜负仍原样成立，指出具体集段和后轮该用到的前轮结果。并行支线分别检查各自的因果和切换。对照已定阶段节奏，看第51–80集加快或放缓后，阶段变化是否仍有场面支撑。
4. **从末场倒查兑现。** 对照开局目标、重要关系、伏笔和承诺，逐项找到兑现的集场。第80集要看见主角用前文建立的能力、选择或资源解决核心矛盾，生活有何改变，最后一场和末句怎样收住故事。逐个长期反派查他各轮所失及剩余筹码，从其选择追到大结局破产、基本生计难以维持的实际场面。例如卖店抵债后，靠什么维生，住处又有什么着落？一次性反派看当轮的实际代价与离场。
5. **退修再核。** 把问题定位到当前稿的集场、原句或动作，标明受影响的前后集。修接法交规划，修正文交写作。拿到修订稿后，复读改处、接点和后续兑现，核对人物口气、事实、情绪和已定卡点，再更新采用的参照及最终 Word。对话中说明实际审完的版本与范围、主要修复及尚待核验之处。

## 核对交付文件

依[正文交付、全剧终检和完本交接](../../references/delivery.md)重开实际要发的 Word。阶段稿与精修稿按本次交付范围核文件名、集序、场头、段落、集间五个空段落和实际字数。从首集标题读到末集正文，对照审过的版本核对关键末句和情绪括号。只交片段时按指定集场和约定核对。

首次交第1–80集纯正文，在发送前按上述交付规则做一次全本机械校验。只对含完整第1–80集正文的 Word 使用，以实际采用的独立参照合计覆盖全剧。报告参照版本、实际覆盖集数、差异及处理结果。工具检查版本、集数、格式和篇幅，剧情与结局由审稿逐集判断。执行方式、字数口径和无法运行时的逐集比对均按同一份交付规则。

全本定稿且用户指示继续，或用户直接给定稿要求整理时，才核正文前资料。按所选栏目回到指定定稿核剧名承诺、年代、称呼、关系、金额性质、梗概集段与结局。只要前置资料时，复核该文件实际栏目、版式及引用的事实。用户要完整版时，核栏目顺序、样式、间距及合入的定稿正文，必要时可用用户确认的全本再次比对。
