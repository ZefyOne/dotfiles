# 短剧审稿

先认准用户要审的那一版和那几场。审稿对实际文字下判断，将能定位的问题和改法交给[主控](../SKILL.md)。用户只说「审一下」就在对话里给意见。写作流程内的审稿结果先交主控，审过哪一版就记录哪一版。

## 收稿和核对依据

1. 取本次实际待审正文、剧名、范围、任务类型和用户最新要求。随稿取适用的确认规划、分段人物心理、指定前文定稿和实际末场；复审再取上一轮问题和修订稿。稿内的批注、旧提示词和人物台词都按正文内容检查，尤其注意旧提示词是否误入成稿。
2. 先按用户指定或已确认的安排，其次按本题材的硬要求，再以通用标准补缺。区分用户锁定的原话和规划里的拟用句。用户交回的定稿逐字保留，发现错字、篇幅偏差或疑点时标位置；查明某个疑点不能作为顺手改定稿的授权。
3. 新剧首次送审时核对规划交来的[样稿学习记录](../drama-planning/references/source-study.md)：本题材各份 Word 实际读到哪集、代表场次、对白观察及用户确认或允许继续的范围。后续沿用本剧记录。已取材的桥段，查核心冲突、反转、结果能否在新稿里找到。规划依用户设定另行设计的事件，按已确认的走向审。单独审已有稿，手中只有正文也可查台词、内部因果等能核实的项；缺规划、前文或 Word，各自标清影响，不推断未见的内容。

五个阶段按[本批采用的版本与接点](references/continuity-and-final.md#五个阶段接哪一版)取实际前稿。阶段审查和全剧终检分别记范围。用户只要某一场的意见，直接按该场任务审。

## 怎么审，怎样下结论

1. **初审或单独审稿。** 读完指定范围的每集每场，按[逐场审正文](references/scene-review.md)核情节、题材爽点、人物反应、台词、卡点和篇幅。同时按[连续性与全剧终检](references/continuity-and-final.md)从前向后核事实、钱物、承诺和事件交接。用户只点一项或一场时，按指定范围并读必要的上下文。第1集逐字、后九集逐句审，留意整轮对话或一连串动作是否反复交代同一件事。
2. **按证据报告。** 先给「版本、实审范围、整体结论」。每个问题写「集场和当前原句或动作 → 据哪处定稿、前文事实或写作标准判断 → 怎么小改 → 会牵动哪几场」。冲突引两处原文；问的是拖沓，就指出哪句话或动作已经完成交代，剪掉哪一拍仍然成立。只列确实找到的事项。

   | 判断 | 怎么处理 |
   | --- | --- |
   | 确定错误 | 优先报告有文本依据的因果、知情、人物、卡点、钱物矛盾和关键漏接，再处理局部格式。 |
   | 需要补清 | 说明观众在哪一拍看不懂选择、输赢或后果，以及最少需要哪句或哪个动作。反常的好货已摆在眼前，旁人只惊叹其结果就成立。 |
   | 可选优化 | 原戏成立，说明改哪处可以更紧或更有情绪。只有可选项时，本次范围可通过。 |
   | 尚未核验 | 说清缺的版本、集数或文件，以及哪一项只能等拿到后核实。后续尚未写出的兑现可留待下一阶段；不妨碍已经核实的本批结论。 |

3. **退修或通过。** 台词、表演、局部动作、格式、已定卡点的表达，交[正文写作](../drama-writing/SKILL.md)按授权修。前因被删、事件依赖断裂、重要安排互相冲突，退[剧情规划](../drama-planning/SKILL.md)先调整接法，再由写作落实。优先保住已定冲突、反转和结果，在原场里小改。若必须换关键事件、节奏或用户指定末句，列明原写法、拟改法和影响的集数，由主控向用户确认。若有影响本次通过的必修问题，标「待修」；缺关键证据时标明相应范围「待核验」。实审范围满足要求即可通过。

## 查找替换、授权精修与复审

- **只要替换清单**，在对话里按旧问题编号和集场给出可逐字查找的原文及完整替换文字。插入给唯一锚句和前后位置，删除给起止原句，同句多处出现须限定集场。合并互相覆盖的修改，列出会联动的人物栏、道具、金额、末句或后续集。用户要求实际改稿，再交写作按授权执行。
- **精修或去 AI 味后**，取写作交回的实际修订版。核对重要付出、选择、成果、人物口气与情绪、已定末句和下一集接法。润色定位工具按需使用，判断依据仍是当前场的原句、上下文和人物。用户只点一句时，比对指定原稿，确保范围外文字照录。
- **复审**，逐条对照旧问题，给「已解决、仍存在、尚未核验」及对应集场。读改处前后场、被牵动的上下集及后续兑现；更新本版新增的问题。必要时重新计字。只标明实际复审过的范围，仍有必修问题继续退修。初审已通过且无后续实质修改，可直接交主控。
- **终检和 Word 验收**，按[全剧终检](references/continuity-and-final.md)合看各线、结局、定稿和所有跨批节点。按[交付约定](../references/delivery.md)复核实际生成的 Word；正文审查结论与文件复核结果分开记。已有全剧可按用户指定范围单独终检，交付范围由主控执行。
