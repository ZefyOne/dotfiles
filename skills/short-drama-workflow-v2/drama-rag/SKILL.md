# 短剧资料检索

先确定本次允许读取哪些资料，再按任务找原文。用户指定只看某份稿、某个题材或某段集数时，沿用这个范围。以下命令均在 v2 的根目录执行，索引路径示例为当前工作位置下的 `.rag/rag.sqlite3`。

## 建库与更新

`assets/<题材>/` 下放同题材样稿，支持 Word（.docx）、Markdown 和 UTF-8 文本。可以直接使用已有文档。若只允许用某个题材或某份定稿，用 `--source` 限定建库范围。范围不同的项目各用自己的索引文件。只允许一份稿时，检索也用 `--source` 指明该文件。

```bash
python3 drama-rag/scripts/build_index.py --root . --source "assets/鉴宝" --index .rag/rag.sqlite3
```

添加、编辑或移除样稿后，沿用原路径与范围，运行 `update_index.py`。它在扫描的目录内更新变动，清理已移走的文件。已有旧版索引也用这条命令升级，原文无需转换。

```bash
python3 drama-rag/scripts/update_index.py --root . --source "assets/鉴宝" --index .rag/rag.sqlite3
```

`--source` 可重复，省略时读取工作流的 `assets/` 和子模块的 `references/`。需要核对当前项目时，可用 `--project-dir` 指定项目资料，或用 `--source` 逐个列出本次获准使用的文件。`--rebuild` 会用本次列出的来源替换整个索引，通常更新用上面的增量命令即可。

## 找符合主编风格的戏

1. 先从当前规划或待改台词中写出一个具体交锋。例如把“对白更有拉扯”落到“买家压价，卖家收起东西要走，买家改口挽留”。如果主编指定亲手改过的样稿，直接用它的来源路径，把题材和集数限制也带上。
2. 用 `--mode style` 查样稿。默认最多返回三段，每场选一段。可以找到整组动作时，只返回整组命中的片段。只能找到部分动作时，结果会列出缺了哪一拍。需要控制参考集数时传 `--episode-range`。续写到第31集也可以参考样稿前十集。
3. 按原文读出谁先开口、哪句话或哪个动作逼对方改变决定、该在哪一拍停。把值得借鉴的一两点连同原文和出处交给请求方。剧情事实沿用当前剧的定稿，人物、物品、金额和台词要按当前场面重新写。
4. 搜不到或原文只有字面相似时，可以在同一授权范围内改用人物可能说的短句再搜一次。仍无合适样稿，说明本次缺少对应参考，继续依据主编给的要求处理。

```bash
python3 drama-rag/scripts/retrieve.py --index .rag/rag.sqlite3 --mode style --genre 鉴宝 --episode-range 1-30 --query "买家压价，卖家要走，买家开口挽留"
```

若主编点名某份定稿，使用索引显示的文件路径。显式指定来源的写法也适用于被主编选作风格参考的当前项目正文。

```bash
python3 drama-rag/scripts/retrieve.py --index .rag/rag.sqlite3 --mode style --source "assets/鉴宝/主编定稿.docx" --query "当众羞辱"
```

## 核对事实和交接

查人物何时知情、道具归谁、某集如何结束时，按本剧的人名、物件或原句检索。用 `--source` 指定采用的本剧版本，可加 `--episode-range`。需要规则时可用 `--source-type rules` 和 `--stage writing`。用户的当前指令直接带入任务，主编锁定的正文和规划优先于样稿。审稿时按播放顺序读完指定范围。整理正文前资料时，沿用用户指定的正文边界。

```bash
python3 drama-rag/scripts/retrieve.py --index .rag/rag.sqlite3 --source "当前项目/正文定稿.docx" --episode-range 第二集 --query "押金"
```

普通输出包含原文、来源、版本、已识别的集号和场号。版本是文件内容的指纹，定稿身份以主编指定为准。加 `--json` 可获得结构化结果。未命中返回零条及原因，未核实的场次或事实保留待核验。

本地 SQLite 索引按字词检索，用 BM25 排序。风格检索还识别 `config.json` 的 `style_cues` 中列出的常见动作与说法。动作标签用于查找可能的对白，风格是否合适由读到的原文判断。调整这些说法后，用同一范围执行增量更新。整个检索过程可离线运行。
