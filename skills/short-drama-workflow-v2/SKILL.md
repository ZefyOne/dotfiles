# 短剧工作流入口

本目录是一套完整的短剧创作工作流。根文件只负责识别任务、调用主控或指定子 skill，不在这里另写一套剧情标准。所有模块使用同一套项目事实、版本和交接规则。

## 默认入口

用户提出以下任务时，优先调用 [主控 skill](drama-controller/SKILL.md)：

- 写一部新剧
- 接着当前项目往下写
- 从规划到正文、审稿、返修和交付完整推进
- 继续某部剧的下一阶段
- 合并全本并做最终交付

主控负责判断当前阶段，协调规划、写作和审稿，不要绕过主控自行改变已确认的核心事件、人物关系或卡点。

## 单独入口

用户明确只做某一项工作时，按下表进入对应流程。

| 用户要做的事 | 调用入口 | 返回给谁 |
| --- | --- | --- |
| 排剧情、排前十集、排分集、排卡点、调整后续走向 | [drama-planning](drama-planning/SKILL.md) | 直接给用户，或交回主控 |
| 写正文、续写、改稿、改台词、去掉水话和 AI 味 | [drama-writing](drama-writing/SKILL.md) | 交稿时标明待审或待复审 |
| 审稿、复审、查连续性、查卡点、全剧终检 | [drama-review](drama-review/SKILL.md) | 标明通过、待修或待核验 |
| 根据剧本正文整理正文前资料 | [主控](drama-controller/SKILL.md) 调用 [drama-front-matter](drama-front-matter/SKILL.md) | 默认由主控单独交付资料 Word；明确要会话文本时直接输出 |

直接使用子 skill 时，用户给出的实际正文、规划、前稿、集数范围和修改要求优先。缺少会影响判断的材料时，只补问必要内容，不强行启动完整创作流程。

## 模块之间怎样接续

完整工作流按下面的顺序运行，具体集数可按用户要求缩短：

```text
主控
  → 剧情规划
  → 用户确认规划
  → 正文写作
  → 初审
  → 返修
  → 复审
  → 通过后的最终语言精修
  → 阶段精修稿待主编确认，确认后锁定并进入下一批
```

最后一批完成后，主控合齐全剧正文，默认调用 `drama-review` 做全文核对。核对修订完成后把正文交主编确认；确认全剧定稿后再据此单独整理正文前资料。单批交付按当次范围，默认给只含正文的 Word。主编已有定稿、单独要求整理资料时，直接采用指定版本。

模块交接时必须带上以下内容：

- 本次任务和集场范围
- 采用的正文或规划版本
- 已确认的人物关系、称呼和人物心理
- 本剧持续生效的要求、人物知情、钱物记录和未兑现事件
- 用户锁定的原话、卡点和不可改动事项
- 本次实际完成的内容
- 上次交付物、当前待确认事项和状态，区分审核通过、精修待确认、主编已锁定
- 下一步应接的集场和动作

## 调用规则

1. 只要用户要求完整推进项目，先调用 `drama-controller`，由主控决定是否进入规划、写作或审稿。
2. 用户明确指定某个子任务时，按单独入口表执行，只处理所需阶段。
3. 子 skill 发现问题超出本次授权时，保留问题和影响范围，交回 `drama-controller`，不能自行改动已确认的核心走向。
4. `drama-controller` 负责阶段协调、版本记录、返修分派、定稿确认和 Word 交付。整剧收尾或主编单独要求时，由 `drama-review` 执行全文核对。
5. 子 skill 完成后必须返回实际范围、采用版本、完成状态和待接事项，不能只回复“已完成”。

## 读取方式

- 进入完整流程时，先读 `drama-controller/SKILL.md`。
- 只做规划时，读 `drama-planning/SKILL.md` 及其需要的 references。
- 只写正文时，读 `drama-writing/SKILL.md` 及其需要的 references。
- 只审稿时，读 `drama-review/SKILL.md` 及其需要的 references。
- 只整理正文前资料时，先读 `drama-controller/SKILL.md`，由主控调用 `drama-front-matter/SKILL.md`。
- 题材规则、样稿、Word 交付和机械检查脚本按各模块中的相对路径读取。
