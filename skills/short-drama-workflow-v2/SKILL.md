# 短剧主控

先认准本剧、任务范围及用户已经确定的版本。按“本次用户指定与已确认安排 → 对应题材的剧情设计逻辑 → 通用默认值”执行。每次只给用户当前需要判断的内容。规划、案例、意见和进度在对话里交。Word 保存到本剧项目目录，交付时按[Word 附件交付](references/delivery.md#word-附件交付)在当前对话的回复中直接附上 `.docx` 文件。需要保存时才核实尚未明确的目的地。

## 四个工作入口

本文件是整套短剧工作流的总入口。下表的模块路径均相对于本文件所在的根目录。每次进入对应工作时，读取该模块的入口及它要求的材料，将表中需要的实际内容交过去。同一会话也按这些步骤执行。预留入口在对应模块可用时启用；入口缺失就说明已走到哪一步、缺哪一项，只记录确实完成的工作。

| 入口 | 传入 | 接回 |
| --- | --- | --- |
| [剧情规划](drama-planning/SKILL.md) | 题材、用户原话与已确认设定、当前阶段、实际前稿和新增反馈 | 确认所需的案例、年代与人设、当前规划；内部留存全剧粗纲、逐段因果、人物态度及对白参考场次 |
| [正文写作](drama-writing/SKILL.md) | 已确认的本阶段规划或后五十集大纲下的内部逐集安排、分段人物心理、锁定原话与拟用台词、实际前稿、题材标准、相关素材原场或定位；返修时加原稿及审稿意见 | 标明版本、集场和承接位置的实际正文（待审），或附修改位置的修订稿（待复审） |
| [审稿](drama-review/SKILL.md) | 实际待审稿、同一版规划、用户指定的前稿和要求；复审时附旧问题、改动位置及当前版本 | 实审版本与范围、通过或待修、未核验项，以及具体集场的证据、改法和影响范围 |
| 完稿资料 · `drama-front-matter/SKILL.md`（预留） | 用户指定的全本或集段、已有基本人设、要整理的栏目和交付形式 | 只依定稿写成的剧名、备选剧名、年代背景、简介、人设和分段梗概，或用户指定的子集 |

## 启动新剧

1. 只说“写一部新剧”时，第一轮只问题材。题材已知就交规划通读同题材素材，在对话里交少量有来源的代表案例，等用户认可理解。保留已给的简介，避免重复问。
2. 由规划收齐剧名或暂名、简介、开局、主要关系、金手指的功能和用户认定的爽点。线数未明确时问清双线还是三线。由 AI 依据题材节奏表提出前十集的默认节奏与剧情循环，给用户调整；用户指定的排法优先。
3. 让规划内部先排通第1–80集的主要事件、各线的发展、重要人物和结局。AI 据此交一版年代背景及主要人设（姓名、身份与关系、年龄、性格），等用户明确确认。用户改人设时先调顺受影响的粗纲。开写前另有本阶段剧情确认；“人设可以”只确认人设。

## 五个阶段如何接续

| 本阶段 | 从哪里接，给用户看什么 | 按下节写审后怎样交接 |
| --- | --- | --- |
| 第1集 | 从确认过的设定和人设出发。给首集详案，写清受挫、关系变化、觉醒和集尾拟用末句，确认后开写。规划已考虑第十集的呼应。 | 交第1集，主动确定哪一版第一集用于续写。手改定稿也是后面人物口气的依据。 |
| 第2–10集 | 读指定的第一集原文和末场，调整后九集，逐集给剧情、卡点，按事件给人物心理，等确认。默认第十集在首集反派见证主角优势后的震惊处收住，后果留给十一集。 | 默认按本次实际新写范围交第2–10集；用户要累计前十集就原样合入第一集。主动确定第1–10集定稿。 |
| 第11–30集 | 从指定的前十集实际结尾接。给本批逐集剧情、分段人物心理和卡点，等确认。 | 交第11–30集，主动确定第1–30集定稿。 |
| 第31–50集 | 读指定的前三十集。规划更新后续，在对话里一次提交第31–80集按事件分段的大纲，含人物心理、实际结果、承接和结局。确认后内部细化第31–50集到每集卡点。 | 本批同样写审。把审过的修订稿留作内部工作稿，与指定的前稿接成第1–50集，核对第50集末场。 |
| 第51–80集 | 沿用已确认的后五十集大纲，从内部前五十集实际正文接，内部细化并执行本批。 | 本批通过后合并全剧，走[终检和交付](references/delivery.md)。正文定稿且用户指示继续后，才进入完稿资料。 |

前1、10、30集三个交接点，主动问“接下来以哪份为定稿？”用户对本次交接已明确指定附件、路径、某版对话正文或几份分批稿，就直接采用并读到实际文字。“规划可以”对应的是刚发的规划。范围只确认一部分，就标出已确认与尚待确定的集场。用户定稿原文逐字接入，字数偏差、错字或疑点只指出位置；用户明确要求改哪一处才动哪一处。剧情可以跨过任一阶段边界。

## 每个阶段都走同一轮写审

1. **确认规划后写。** 交给用户的具体规划按事件单列「人物心理」，打脸段标明起因、发展、高潮、结果。「简单点」「只重发这几集」也使用规划模块的[短版格式](drama-planning/references/templates.md#局部修改与简短重发)。写作按通过的规划及实际前稿落笔，每段对手戏带上相近素材的出处或完整一轮对白。
2. **初稿完成后逐场精修。** 每批新正文写完，由正文写作按[初稿完成后逐场精修](drama-writing/SKILL.md#初稿完成后逐场精修)从本批首集改到末集。单集和指定场次按本次范围执行。
3. **送审精修后的正文。** 对照用户要求、题材、规划、定稿和衔接，从本批首集审到末集。要求审稿给出实际核验的范围和具体发现，区分妨碍通过的问题与可选润色。待核实事项写明集场。单纯的“已生成”、脚本跑完或局部抽查都不能记作整批通过。
4. **按问题退回。** 台词、情绪、动作或已定卡点的写法有问题，交写作改。前因已撤销、剧情依赖错误、事件接不上，交规划先修接法，再由写作修文。用户的反馈按局部、后续受影响集段或全剧约定分别处理。内部未定走向可直接调，越出用户授权要改已定的核心事件、节奏或末句时，只提具体改法及影响，请用户确认。
5. **复审修订稿。** 读改后的实际文本和受影响的上下场、上下集与后续兑现。语言润色也在最终复审前完成；去 AI 味工具按需要定位，修文仍交写作。仍有必修项就继续退修。初审已通过可直接进入交付或内部接续。记录通过的是哪份版本；任何后续实质改动都复核后再交。

## 进度和指定任务

在本剧的对话交接中记住：当前阶段及步骤、本次规划的确认范围、正文采用的版本和位置、本批审查状态、用户修改及其适用范围、上一集末场和下一步。跨阶段带上未兑现的事件、人物知情与态度、钱物归属、反派已付的代价、素材出处及可回读的原场。全剧粗纲随前文定稿更新。项目已有进度记录时可接用，正文事实以指定原文为准。需要用户判断才展示相应条目。中断后从实际完成处恢复。

- **只审已有稿、查找替换或复审**，直接交审稿处理指定版本和范围。只要意见就在对话中交意见；用户要求修改才让写作改并复审。
- **单独精修已有稿或去 AI 味**，把用户指定的原稿和范围直接交正文写作逐场精修。另存修订版，按改动范围送审。
- **只写指定集场或中段续写**，取用用户指定的可读正文与规划；缺哪项只核实哪项。单独从第51集接写，采用用户指定的前五十集，只确认第51–80集的分段安排，可按要求只交后三十集。有完整参照时也可以做全剧终检。
- **已有完整正文，只需前置资料**，采用用户这次指定的版本，直接进入完稿资料。意见与资料按用户要求在对话中交付，指定 Word 时交相应文档。
