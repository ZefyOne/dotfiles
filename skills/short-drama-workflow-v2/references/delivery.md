# 正文交付、全剧终检和完本交接

收到对应版本的审稿通过结果后，按实际交付范围执行。输出到本剧项目目录，用户要在对话里看某集或只要局部时遵从本次要求。

## Word 附件交付

阶段稿、返修稿、全本和单独的前置资料，凡要以 Word 交给用户，都先打开并核对本次要发的 `.docx`，再将同一份文件作为附件直接发在当前对话的回复里，显示完整文件名（含扩展名）。用户应能从这条回复直接下载 Word，无需进入另一个 GPT 窗口、画布或分享页面。只有实际附上文件才算交付。附件发送失败时，重试发送同一文件；仍未成功就说明附件未发出。

## 阶段稿

- 默认把实际正文保存为可下载的 `.docx`。单集用 `1 剧名.docx`，多集用 `2-10 剧名.docx`、`11-30 剧名.docx` 等；用户要求累计稿则使用其实际范围。分批名可用题材暂名。集号和名称间用一个半角空格，同范围再交修订版要能区分版本。
- Word 从首集集标题开始。按实际文件核对中文集标题、场次编号、时空、场景、人物四行场头，时空限日/内、日/外、夜/内、夜/外。动作以 ▲ 起行，动作、对白和 OS 各自成段；一集通常一至两场。正文采用宋体五号、1.5 倍行距。相邻两集之间恰好五个空段落。
- 打开本次要交的文件，核对实际集号、顺序、场次、空段和各集正文。新写完整集目标 1030 字，1000–1060 字，含标点。计动作、对白、OS 和特效；去掉集标题、场头、行首标记、说话人标签（含情绪括号与分隔符）和空白。按用户指定的其他口径执行本剧。用户定稿的偏差只报告。
- 在对话里给实际 Word、审查的版本与范围、本批总字数、超出约定的集号、主要修复和待确认事项。第31–50集的工作稿仅用于内部接写。

## 合交全剧

1. 取用户指定的第1–30集原文及审查通过的第31–50、51–80集修订稿，保留各自的独立参照。定稿可由多份连续分批稿组成。单独接写后三十集并合全本时，采用用户指定的前五十集。确认全文时用户也可指定一份现成全本。
2. 交审稿做全剧终检。按实际全剧读完，查从开局到第80集的目标、各线、未兑现事项、每个长期反派破产和基本生计难以维持的实际结局。连读第1→2、10→11、30→31、50→51集及实际的高潮和收尾，核对知情、道具钱物和动作的传递。发现问题按主控退修、复审，更新参照和最终 Word。
3. 首次只交正文，文件名为 `1-80 剧名 YYYYMMDD.docx`。日期取用户所在时区实际发稿日，八位连写。用户已给正式剧名就用原名；用户指定暂名则沿用该名称。核对全剧正文总字数 80000–85000，实际合稿中用户定稿偏差照实列明。按上节重开 Word，确认五个空段等排版。
4. 发全本前，从本技能目录运行[版本比对脚本](../scripts/check_screenplay.py)。给每份实际采用的独立参照标上集数，让范围合计覆盖1–80。示例：

   ```sh
   python3 scripts/check_screenplay.py "1-80 剧名 YYYYMMDD.docx" --episodes 1-80 --check-length --full-coverage \
     --reference "1-30 定稿.docx" --reference-episodes 1-30 \
     --reference "31-50 内部修订稿.docx" --reference-episodes 31-50 \
     --reference "51-80 内部修订稿.docx" --reference-episodes 51-80
   ```

   独立参照来自对话时，可按指定文字暂存供核对。退出码 0 为通过，1 为发现差异，2 为输入或读取错误。先核实集号、参照版本和正文；若只有用户已定稿字数偏差，保留原文并注明。脚本不可用时以实际独立参照逐集核对，并如实报告覆盖范围。此脚本只查全本文件，审稿仍需读正文。

## 正文前资料

全本定稿并得到用户继续指示后，或用户直接指定成稿来整理时，将版本和所选栏目交完稿资料入口。常规快速提取剧名、备选剧名、年代背景、简介、人设和分段梗概。初始基本人设供对照，小传、转折和结局按最终正文。

只要前置资料 Word 就只交指定栏目；要求完整版再合入定稿。重开文件核实字段、排版、关键事实。完本稿用 Word 正文样式（Normal）、宋体五号、1.5 倍行距，仅栏目名加粗。相邻栏目空两行，相邻人物空一行，“正文”与第一集之间空一行，集与集之间空五行。合入全本后必要时用指定定稿再比对一次。
